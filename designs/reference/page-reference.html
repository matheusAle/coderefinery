§02 · coderefinery
Four gates. One binary. Exit codes.
$ coderefinery crap --changed
Is it too complex for its tests?
counts every decision, reads the coverage report, scores CRAP per function. ≥ 10 → exit 2.
after Alberto Savoia's CRAP (2007) and Uncle Bob's crapper (ub-mode, 2025)
$ coderefinery dry --changed
Is it a copy with new names?
normalises each function's syntax tree, erases names and literals, compares every pair. ≥ 0.8 → in the report.
after dry4clj and Uncle Bob's dryer
$ coderefinery mutate --changed
Would the tests notice a bug?
flips operators and constants one at a time, runs the suite per mutant, re-runs only survivors and changed functions. survivor → exit 3.
after Uncle Bob's mutator; the idea is from 1978
$ coderefinery tests (preview)
Does this test catch anything?
attributes every kill to the tests that caused it. a test with zero unique kills is listed for deletion. → exit 3.
new. reads JUnit XML from any runner.
what it does
gates the diff
--changed on every command. a ten-year codebase never passes a repo-wide mandate; a PR can.
refuses, then explains
exit code first, line numbers second. the agent reads both and fixes the code, not the gate.
runs where the agent runs
a hook in Claude Code or Cursor, the same three commands in CI. one binary, no runtime.
stays honest
byte-identical to the reference tools on 36/36 cases. 3–120× faster, measured on 12 repos.
what it refuses to be
a coverage %
agents write assert True to hit 90 %. the gate asks whether the test can fail.
another AI reviewer
no model in the loop. same input, same verdict.
a repo-wide audit
it does not grade your legacy. it grades the change.
a warning
a warning is a suggestion. an exit code is a decision.
