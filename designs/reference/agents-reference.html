§ for agents · why determinism
The agent gets the same answer every time. So it learns the rule, not the reviewer.
An agent optimises for the signal it gets. A reviewer it can persuade teaches it to persuade. A formula it cannot move teaches it to move the code. coderefinery gives every edit a number, a threshold, a line, and an exit code. Same input, same verdict, on your laptop and in CI.
repeatable
same tree in, same number out. byte-identical to the reference tools on 36/36 cases.
local and fast
seconds on --changed. the agent runs it after every edit, not once before the commit.
precise
file:line, the metric, the threshold it crossed. nothing to interpret.
un-gameable
the only way to change the number is to change the code or the tests.
machine-readable
exit codes for the hook, .metrics/*.edn for tooling, stdout for the transcript.
● no model in the loop · the gate does not read the PR description

§01 · the loop the agent lives in
Edit. Gate. Read the exit code. Fix the code, not the gate.
1 · edit
the agent changes code or tests. nothing else is in scope.
→
2 · gate
crap · dry · mutate · tests, on --changed only. seconds.
→
3 · verdict
exit 2 · report · exit 3 · exit 0, with file:line and the number.
→
4 · fix the code
split, merge, add the assertion, delete the dead test. never edit the gate.
→
5 · commit
the hook re-runs the gate. exit 0 is the only way through.

§03 · reliable tests, mechanically
The mutant tells the agent which test to write.
A surviving mutant is a precise specification of a missing assertion. The agent does not have to guess what a good test is; it reads the edit that went unnoticed and writes the case that would notice it.
surviving mutant
the test it demands
< → <=
a case exactly on the boundary. the equality is the bug.
0 → 1
a case where the result must be zero, not merely small.
and → or
each operand alone: one true, one false, assert the branch is not taken.
− → +
an expected value that changes sign or direction, not one that happens to match.
true → false
both branches observed through the result, not through a spy.
delete not
the negated input, asserted on the outcome.
== → !=
a case that is equal and a case that is not, with different expected results.
delete −x
a negative input whose sign reaches the output.
what the skill says
what enforces it
write the failing test before the code
mutate: a test written after the fact that cannot fail has zero kills
test behaviour, not implementation
tests: a spy on a private call kills nothing; it is listed for deletion
if it would pass with every function returning nothing, throw it out
tests: zero kills, exit 3
split before you test
crap: CC ≥ 10 cannot pass at any coverage
one body, two names is one body
dry: 0.8 on the normalised tree, names erased
delete what no honest test can kill
mutate: a survivor nobody can kill marks dead code
test the diff, not the repo
--changed on every gate; the hook runs in seconds
● the skill is advice. the exit code is the enforcement. the research found no other way that survives contact with an agent.

§04 · same everywhere
Your laptop, the hook, CI: one binary, one answer.
no runtime

no clock, no dice
